## 三、几个非显然的点（下一手别踩）

1. **GB2312 不能省**：表单 `RadioButtonList1` 的值是中文「学生」，整个 body 必须按 GB2312 编码；用 UTF-8 会一直登录失败且服务器只回「验证码不正确」，很难定位。
2. **两个站点的地址形态不同**：
   - 金山学院：根路径 200，无会话前缀，`<form action="default.aspx">`
   - 校本部：根路径 302 到 `/(一长串ID)/default2.aspx`
   → 所以 `loadLoginPage()` 不写死路径，登录 action 与验证码 src 都从页面现抓（`formAction()` / `captchaSrc()`）。
3. **前缀正则必须吃掉前导斜杠**：`https?://[^/]+(/\([^)]*\))/`，否则拼出 `http://jwgl.fafu.edu.cn(ID)/` 少一个斜杠，连不上。
4. **不依赖 Cookie**：服务器基本不下发 Set-Cookie，会话靠 URL 里的 `(ID)` 目录，所以 `absoluteUrl()` 必须用 `URL(URL(cur), loc)` 正确解析，不能字符串拼接。
5. **校验顺序是先验证码后密码**：所以自动化探测永远只会拿到「验证码不正确」，无法用假账号验证密码字段——判断依据是「字段名/编码/地址都对时才会走到验证码提示这一步」。
6. **导入不写学期起始日**：教务课表只有周次，学期起始周来自本机 `ScheduleStore.termStart`，导入前若没设对，周次注释会偏。
7. **替换导入前先备份**：沿用 `doImport` 的 `SharedPreferences("schedule").courses_backup` JSON 结构（不是 `ScheduleShare` 编码），「从备份恢复」才能救回来。
